# Artist Lead Finder

Локальное приложение для Windows и macOS (Apple Silicon) для поиска и оценки независимых артистов.
Текущий интерфейс оформлен в тёмной теме.
Рабочий локальный MVP: веб-поиск публичных Instagram-профилей, сбор из браузера,
демонстрационный поиск и импорт CSV/JSON, фоновые
задания с паузой/отменой, анализ правилами, оценки с breakdown, фильтры,
история, ручные CRM-статусы и CSV-экспорт. Реальный Instagram API и AI не
подключены. Демонстрационные профили вымышлены. Рассылки и engagement нет.

## Разработка
Нужны Node.js, Rust stable (MSVC), Visual Studio C++ Build Tools и WebView2
для основного окна Tauri. Для окон Instagram приложение использует
собственный Chromium, управляемый Playwright.
`npm ci`; создайте `.venv` Python 3.12: `python -m venv .venv`.
Установите зависимости: `.venv/Scripts/python -m pip install -r backend/requirements-lock.txt`,
затем `.venv/Scripts/python -m pip install -e backend --no-deps`.
Загрузите Chromium для разработки и сборки: в PowerShell выполните
`$env:PLAYWRIGHT_BROWSERS_PATH='0'; .venv/Scripts/python -m playwright install chromium --no-shell`.
Запуск: `npm run desktop:dev`.
Проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.
Ядро: `.venv/Scripts/python -m pytest backend/tests -q` и
`.venv/Scripts/python -m ruff check backend`.
`npm run dev` запускает только frontend для разработки, это не desktop.
Снимки всех экранов на тестовых данных (без ядра и Instagram):
`.venv/Scripts/python scripts/ui-preview.py <папка> [ширина высота]`.

Для запуска без установки откройте
`artifacts/ArtistLeadFinder-Portable/artist-lead-finder.exe`. Файл
папка `core` должна оставаться рядом с ним. Данные сохраняются в
LocalAppData текущего пользователя Windows.
Seeded data: `.venv/Scripts/python -m artist_lead_finder --generate profiles.json --count 1000`.
Импорт: JSON array или CSV, обязательные platform и username; поля Candidate
описаны в backend/artist_lead_finder/providers.py. URL только HTTP(S), до 25 MB.
CSV recent_content при необходимости оставляйте отсутствующим; JSON поддерживает
массив строк. В настройках включите импорт после выбора файла и сохраните.

Архитектура и упаковка описаны в ARCHITECTURE.md. Ход работы —
IMPLEMENTATION_PLAN.md. Упаковка: `npm run package:windows`, см. PACKAGING.md.
Публичный релиз требует подписи и проверки на чистой Windows.

На macOS (разработка): `.venv/bin/python` вместо `.venv/Scripts/python`, в остальном те же команды;
сессии Instagram и ключ AI шифруются ключом из Keychain вместо DPAPI.

## Релизы и автообновление
Выпуск новой версии:
1. `node scripts/bump-version.mjs 0.2.0` — версия во всех манифестах; закоммитьте.
2. `git tag v0.2.0 && git push origin main v0.2.0` — GitHub Actions (`.github/workflows/release.yml`)
   собирает Windows-установщик и macOS `.app`/`.dmg` (Apple Silicon), подписывает пакеты
   обновления и создаёт черновик релиза с `latest.json`.
3. Проверьте черновик на GitHub и опубликуйте его. Установленные приложения при запуске и
   каждые 6 часов видят новую версию: в верхней панели появляется «Обновление X», установка
   и перезапуск — по кнопке. Вручную: «Настройки» → «Проверить обновления».

Ключ подписи обновлений (не Apple и не Windows code signing) создан командой
`npx tauri signer generate` и лежит вне репозитория: `%USERPROFILE%/.tauri/artist-lead-finder.key`
и `.password`. Их содержимое нужно добавить в GitHub → Settings → Secrets and variables →
Actions как `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Публичный ключ —
в `src-tauri/tauri.conf.json`. Сохраните резервную копию ключа: без него установленные копии
не примут ни одного обновления.

Установка на Mac: откройте `.dmg`, перетащите приложение в «Программы». Сборка без подписи
Apple, поэтому при первом запуске macOS его блокирует: «Системные настройки» →
«Конфиденциальность и безопасность» → «Всё равно открыть» (на macOS 14 и старше также ПКМ →
«Открыть») или в Терминале `xattr -dr com.apple.quarantine "/Applications/Artist Lead Finder.app"`. Дальнейшие обновления
ставятся без этого шага. При первом запуске на Mac приложение само скачивает Chromium
(~150 МБ, пара минут); до конца загрузки окна профилей не открываются.

## Браузерные профили и cookies
Откройте раздел «Аккаунты», нажмите «Новый профиль», задайте название и при необходимости вставьте
прокси одной строкой, затем создайте профиль. После этого
можно открыть браузер и войти вручную либо нажать «Импорт cookies» у нужного профиля.
Прокси можно вставить одной строкой в форме создания или настройки профиля:
`socks5://user:password@proxy.example.com:1080` либо
`user:password@proxy.example.com:1080` (без префикса используется SOCKS5).
Для HTTP укажите `http://` или выберите тип. Принимается и `host:port` без
авторизации. Строка видна в поле до сохранения; после сохранения пароль обратно
не показывается.
Для прокси с авторизацией приложение поднимает локальный посредник на 127.0.0.1:
он передаёт HTTP Basic или SOCKS5 username/password на указанный прокси.
Пароль хранится внутри Windows DPAPI и не возвращается в интерфейс.
Менять прокси и импортировать cookies нужно при закрытом окне профиля.
Поддерживаются JSON array (или объект с массивом cookies) и Netscape cookies.txt,
до 1 MB. Принимаются только домены instagram.com и его поддомены; истёкшие
cookies пропускаются. Приложение не читает cookies установленных браузеров.
Исходный файл пользователь выбирает самостоятельно, он не удаляется.

Профили хранятся в LocalAppData/ArtistLeadFinder/browser-sessions как файлы
Windows DPAPI текущего пользователя. Cookies не возвращаются React-интерфейсу,
не входят в CSV и настройки и не записываются в журнал.
«Открыть браузер» открывает отдельное окно Chromium с изолированным
контекстом для каждого профиля. Проверьте авторизацию на самой странице Instagram;
наличие sessionid не считается доказательством успешного входа.
Сессия сохраняется автоматически, когда окно профиля закрывают (и при выходе из
приложения). Кнопка «Сохранить сессию» сохраняет её сразу, не закрывая окно.
Сохраняются cookies; localStorage и другие данные страницы не переносятся.
Перед удалением сохранённой сессии закройте её окно. Удаление локальной копии
не отзывает сессию на сервере Instagram. DPAPI не защищает от программ,
работающих с полномочиями того же пользователя Windows.

Fingerprint не подменяется.

## Основной сценарий: Lead Scout
Раздел «Lead Scout»: SMM-источники → связанные профили → проверка артиста →
фильтры → лид в базе. Scout никому не пишет; сообщения отправляются только из
«Первичной рассылки».

**Источники.** Добавьте аккаунты музыкальных медиа и пабликов (по Enter или
списком). Для каждого видно: включён ли, когда сканировался, статус и сколько
лидов дал. Источники общие для всех аккаунтов; за запуск берётся N включённых
(«Источников за запуск», по умолчанию 5) начиная с курсора, следующий запуск
продолжает с того места (A B → C D → E F → A B). Если публикации пачки
закончились, а цель аккаунта не набрана, тот же запуск берёт следующую пачку;
он завершается при достижении цели или когда прочитаны все источники вне
кулдауна. Полностью просканированный источник пропускается до конца кулдауна
(24 ч, отключается в настройках).

**Методы поиска** (Настройки Scout). Каждый метод — отдельный провайдер,
который только находит usernames и отдаёт их конвейеру Scout:
- Posts / Reels: сетка источника прокручивается лениво, пока не наберётся нужное
  число ещё не разобранных публикаций (лимит раундов, пауза, остановка без
  прогресса). У каждой публикации — автор и соавторы из шапки поста; автор
  ищется цепочкой: structured data → метаданные страницы → ссылки шапки; если
  автора нет, публикация помечается сбойной, догадок нет. Сам источник лидом не
  становится.
- Tagged: публикации, где отмечен источник (`/<source>/tagged/`); кандидат —
  их оригинальный автор (и соавторы).
- Followers / Following: списки источника с пагинацией, паузой и лимитом.
Источники обходятся по одному: страницы источника, проверка найденных на них
профилей, затем его публикации пачками по 12 (каждая пачка проверяется до
следующей), и только потом следующий источник. Лиды появляются с первого
источника, а остановленный запуск теряет не больше одной пачки кандидатов.
Комментарии и истории не читаются: на практике они почти не давали лидов, а
каждая такая страница стоила паузы. Разобранные публикации (tagged — в отдельном
пространстве ключей) и профили запоминаются. Временные сбои загрузки повторяются
(по умолчанию 2 раза), недоступные страницы пропускаются; вход, checkpoint и
ограничение Instagram останавливают запуск типизированной ошибкой. По каждому
источнику и провайдеру видны метрики: увидено, разобрано, кандидатов, дублей,
уже было, сбоев. Режим отладки сохраняет URL, причину, очищенный HTML и скриншот
при сбое разбора в `LocalAppData/ArtistLeadFinder/scout-debug` (без cookies).

**Проверка профиля.** Профиль читается с его страницы в окне аккаунта;
проверенный профиль кэшируется, и повторно страница в пределах срока кэша не
открывается. Web API Instagram не используется. Итог: имя, биография, внешняя ссылка и bio-ссылки
(Linktree, Spotify, Bandcamp…, без дублей, редиректы l.instagram.com
разворачиваются без перехода), подписчики / подписки / публикации числами
(«1,2K», «2,1 тыс.»), категория, бизнес/закрытый, id, до 3 последних подписей,
e-mail (публичный, бизнес, из биографии) и телефоны (E.164, если страна известна,
иначе очищенная исходная строка). Профили кэшируются в SQLite на 12 ч. Закрытый
профиль сохраняет публичную шапку, но лидом не становится.
Локальный классификатор (набор отдельных правил: артист, релизы, ссылки,
продюсер, username, медиа и сервисы, негативные сигналы) по очкам относит профиль к
artist / producer / media / other, считает уверенность (сила, отрыв от второй
категории, сильные, конфликтующие и негативные сигналы), отмечает неуверенные
случаи и сохраняет доказательства («Bio contains strong artist term: rapper»,
«Spotify link found»…). Медиа и сервисы засчитываются только в музыкальном
контексте. AI (OpenRouter) включается режимом: «Выкл.», «Если не уверен» (по
умолчанию: неуверенный результат или уверенность ниже порога) или «Всегда»; ключ
хранится через Windows DPAPI. Ответ AI проверяется по схеме, при ошибке
допускается один повтор с просьбой исправить формат; сбой AI оставляет локальный
результат. Ответы кешируются по хэшу профиля и версии классификатора; временно
недоступный AI повторяется позже, и подошедший профиль возвращается в запуск.

**Фильтры** — один конвейер, строго по порядку: сам источник → список игнора →
уже обработан → уже есть в CRM → нужные данные (закрытый профиль, неизвестные
подписчики, если так настроено) → подписчики min/max → тип профиля (только
артисты / артисты + продюсеры / все) → минимальная уверенность → «только с
контактами». Первые три проверяются до открытия профиля, остальные без типа — до
AI, так что профиль, который всё равно будет пропущен, не тратит запросы.
Каждый пропуск имеет причину и пояснение («FOLLOWERS_TOO_LOW: 245 < min 500»):
SOURCE_ACCOUNT, IGNORED_USERNAME, ALREADY_PROCESSED, DUPLICATE_LEAD,
MISSING_REQUIRED_DATA, FOLLOWERS_TOO_LOW, FOLLOWERS_TOO_HIGH, WRONG_PROFILE_TYPE,
LOW_CONFIDENCE, NO_CONTACT, PROFILE_UNAVAILABLE / NOT_FOUND / PRIVATE / PARSE_FAILED,
CLASSIFICATION_FAILED. RATE_LIMITED не пропуск: запуск уходит на перерыв.
Прошедший профиль сохраняется в «Базу артистов» со статусом из настроек («Новый»
по умолчанию). Дублей нет: лид узнаётся по Instagram id, иначе по username; если
username сменился, у лида обновляется имя. Повторная находка через другой паблик
добавляет источник в историю лида («Найден через») и обновляет данные профиля,
статус CRM не меняется. Username можно добавить в игнор из карточки лида.

**Аккаунты и прогресс.** Источники — карточки на доске Lead Scout («Массовый»
открывает весь список по одному в строке; «Карточки» сохраняет правки, удалённые
строки удаляются). Настройки Scout и статистика источников открываются с доски.
На вкладке «Аккаунты» у каждого профиля цель «найти N лидов» (копится между
запусками) и кнопка «Парсинг» / «Стоп»; отмеченные галочкой аккаунты запускает
кнопка «Парсинг» на доске (они же отправители «Первичной рассылки»). Под доской
для каждого запуска: Пауза / Продолжить / Stop,
текущий источник и профиль, источники N / M, кандидатов, прочитано, тип
определён, лидов, обновлено, пропущено (с разбивкой по причинам), ошибок.
Пауза и Stop кооперативные: текущее решение по профилю не обрывается на
середине; после паузы запуск продолжается с того же места, после Stop или
закрытия приложения следующий запуск начинает с первого незаконченного
источника, а обработанные профили не повторяются. Аккаунты работают параллельно, у каждого свой темп. Блок «Активность»
показывает события (scout:start, candidate:found, lead:found, profile:skipped…)
и журнал по каждому профилю с сигналами и результатом.

Темп задаётся в настройках («Темп сбора Instagram»): случайная пауза между
страницами (по умолчанию 4–10 с), лимит профилей в час (400) и за запуск (без
лимита). При требовании входа очередь встаёт на паузу: войдите вручную и
продолжите. Если Instagram ограничил запросы (включая HTTP 429), очередь встаёт
на паузу и после продолжения выдерживает перерыв; обходов защиты нет.
Счётчики темпа сбрасываются при перезапуске приложения.

Готовые лиды появляются автоматически, без ручного выбора кандидатов.
Три оценки соответствия услугам — биты, сведение/мастеринг, продвижение —
отделены от общей оценки профиля. Прямой запрос весит до 90, свежий релиз даёт
повод для продвижения (60), демо — для сведения (45), жанр рэп/R&B — слабый
сигнал для битов (25). Это не вероятность покупки или доказательство бюджета.
Отрицания подавляют сигнал. Неизвестная дата, будущая дата и возраст свыше
90 дней снижают оценку. Возраст оценок пересчитывается при первом чтении списка
за день, даже без нового браузерного запуска. Сохраняются цитата, источник,
URL публикации и дата (либо «неизвестна»), email из биографии и ссылка профиля.
Отклонённые и contacted-профили скрыты из списка для работы, CRM не сбрасывается.
До 100 результатов выводятся по приоритету. История не является фоновым
мониторингом: пользователь запускает следующий поиск кнопкой.
Подписи уже прочитанных публикаций берутся из кеша; их правки на сайте не отслеживаются.

Дополнительные инструменты (ручные ссылки, демонстрационные наборы)
перенесены в сворачиваемый блок ниже основного сценария.

## Первичная рассылка: первое сообщение найденным лидам
Одна страница: сверху список аккаунтов (usernames), снизу варианты сообщений.
Аккаунты добавляются вводом с Enter (`name`, `@name` или ссылка на профиль),
списком через «Массовый», из CRM по статусам («CRM Метки») или кнопкой «В
рассылку» для выбранных в «Базе артистов». Каждый новый лид «Локального парсера»
попадает в список сам (настройка «Добавлять новых лидов в список «Первичной
рассылки»», включена по умолчанию); уже известные лиды повторно не добавляются.
Сам по себе список ничего не отправляет — пишет только запущенная рассылка. Цвет метки — состояние: зелёный —
отправлено, фиолетовый — в очереди, красный — ошибка или отправка не подтверждена,
зачёркнутый — пропущен (причина во всплывающей подсказке). «Скопировать
отправленные» и «Убрать отправленные» работают с зелёными метками.

Сообщения: Enter — добавить, Shift+Enter — новая строка; «Массовый» — несколько
сообщений через пустую строку; «Шаблоны» — сохранённые тексты. Переменные
`{{firstName}}`, `{{fullName}}`, `{{username}}`, `{{artistName}}`, `{{followers}}`,
`{{source}}`, `{{profileType}}`; пустое значение заменяется безопасно («there»,
username) или своим: `{{firstName|friend}}`. Варианты раздаются получателям по
очереди. «Настройки» — аккаунты-отправители (несколько — по кругу), их состояние
и темп.

«Рассылка» создаёт кампанию из аккаунтов списка, которым ещё не писали
(отправленные, стоящие в очереди и неподтверждённые не включаются), и ставит её в
очередь; «Остановить» снимает неотправленные — список остаётся для следующего
запуска.

Перед постановкой в очередь и ещё раз перед отправкой лид проверяется: существует,
есть username, нет отметки «Не связываться», общение не остановлено, не ответил,
ему ещё не писали (по всей истории сообщений и статусу CRM — настройка «Пропускать
лидов, которым уже писали»). Как и парсер, «Рассылка» сама открывает окно
браузера аккаунта-отправителя (если аккаунт один, он выбирается сам), перед
каждым сообщением открывает в нём профиль получателя и отправляет оттуда. Не
пользуйтесь этим окном во время рассылки; если закрыть его, рассылка ждёт, пока
окно не откроют снова кнопкой «открыть браузер» в строке статуса. Если в
профиле получателя есть только «Подписаться» и нет «Отправить сообщение», ему
не пишут: получатель отмечается «Нельзя написать — только подписаться», а
рассылка идёт дальше. Заранее это не узнать: кнопку Instagram показывает только
тому аккаунту, который открыл профиль. Очередь отправляет по одному сообщению с паузой между
сообщениями одного аккаунта и лимитом за 24 часа.

Сетевой сбой до отправки повторяется с растущей паузой. Вход, checkpoint и
ограничение Instagram останавливают аккаунт: сообщения ждут, пока вы не решите
проблему в окне и не нажмёте «Возобновить» (ограничение снимается само после
перерыва). Если ответ Instagram не пришёл или приложение закрылось во время
отправки, сообщение не отправляется повторно: получатель помечается «проверьте
вручную», в карточке лида отметьте «Сообщение ушло» или «Не ушло».

После отправки лид получает статус «Написали», дату последнего сообщения, диалог
«Ждём ответа» и запись в истории сообщений (карточка лида → «Рассылка»). Кнопка
«Получен ответ» переводит диалог в «Ответил» и отменяет
запланированные follow-up; «Остановить общение» и «Не связываться» навсегда
исключают лида из рассылок. Отправку самих follow-up выполнит отдельный модуль.

## Сбор артистов из браузера
Откройте «Поиск артистов» → «Реальные артисты из браузера». Выберите сохранённую
сессию или вариант без cookies, затем нажмите «Открыть Instagram».
Найдите артиста вручную и откройте его профиль. Кнопка «Добавить открытого
артиста» читает доступную страницу, запускает анализ и показывает сохранённую
карточку с оценкой. Браузер не обращается к скрытым API и не читает сообщения.

Для очереди вставьте до 100 ссылок на профили или @имён, по одной на строку.
Очередь последовательно открывает страницы в выбранном окне и сохраняет
результаты в базу и историю. Не переключайте страницы этого окна во время
обработки. Есть пауза, продолжение и отмена. Запрос входа/подтверждения,
ограничение сайта, закрытое окно или таймаут чтения приостанавливают очередь.
После проверки браузера пользователь может явно продолжить работу.
При перезапуске незавершённое задание отмечается прерванным; список ссылок и
уже сохранённые результаты остаются в истории. Повторный запуск списка не
создаёт дублей артистов и сохраняет ручные статусы CRM.

Извлекаются доступные метаданные страницы: имя, bio, счётчики и внешняя ссылка.
Поддерживаются английские и русские обозначения счётчиков. Разметка Instagram
может измениться: чтение не гарантировано для любой страницы/локали.
Числа на сайте могут быть округлены. Последняя активность пока не извлекается.
Пропущенные поля отмечаются в карточке; неизвестные подписчики показываются
как «Нет данных», в CSV — пустая ячейка. Оценка неполного профиля предварительная.
Существующие значения не стираются отсутствующими полями нового наблюдения.
Источник instagram_browser можно выбрать в фильтрах базы.

Схема SQLite обновлена до версии 3 (таблицы скаутинга добавлены к browser_queues).
Старая версия приложения не открывает базу более новой схемы.
