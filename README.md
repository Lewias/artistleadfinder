# Artist Lead Finder

Локальное Windows-приложение для поиска и оценки независимых артистов.
Текущий интерфейс оформлен в тёмной теме.
Рабочий локальный MVP: веб-поиск публичных Instagram-профилей, сбор из браузера,
демонстрационный поиск и импорт CSV/JSON, фоновые
задания с паузой/отменой, анализ правилами, оценки с breakdown, фильтры,
история, ручные CRM-статусы и CSV-экспорт. Реальный Instagram API и AI не
подключены. Демонстрационные профили вымышлены. Рассылки и engagement нет.

## Разработка
Нужны Node.js, Rust stable (MSVC), Visual Studio C++ Build Tools и WebView2
для основного окна Tauri. Для окон Instagram приложение использует
собственный Chromium, управляемый Playwright.
`npm ci`; создайте `.venv` Python 3.12: `python -m venv .venv`.
Установите зависимости: `.venv/Scripts/python -m pip install -r backend/requirements-lock.txt`,
затем `.venv/Scripts/python -m pip install -e backend --no-deps`.
Загрузите Chromium для разработки и сборки: в PowerShell выполните
`$env:PLAYWRIGHT_BROWSERS_PATH='0'; .venv/Scripts/python -m playwright install chromium --no-shell`.
Запуск: `npm run desktop:dev`.
Проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.
Ядро: `.venv/Scripts/python -m pytest backend/tests -q` и
`.venv/Scripts/python -m ruff check backend`.
`npm run dev` запускает только frontend для разработки, это не desktop.

Для запуска без установки откройте
`artifacts/ArtistLeadFinder-Portable/artist-lead-finder.exe`. Файл
`artist-core.exe` должен оставаться рядом с ним. Данные сохраняются в
LocalAppData текущего пользователя Windows.
Seeded data: `.venv/Scripts/python -m artist_lead_finder --generate profiles.json --count 1000`.
Импорт: JSON array или CSV, обязательные platform и username; поля Candidate
описаны в backend/artist_lead_finder/providers.py. URL только HTTP(S), до 25 MB.
CSV recent_content при необходимости оставляйте отсутствующим; JSON поддерживает
массив строк. В настройках включите импорт после выбора файла и сохраните.

Архитектура и упаковка описаны в ARCHITECTURE.md. Ход работы —
IMPLEMENTATION_PLAN.md. Упаковка: `npm run package:windows`, см. PACKAGING.md.
Публичный релиз требует подписи и проверки на чистой Windows.

## Браузерные профили и cookies
Откройте вкладку «Профили», задайте название и при необходимости вставьте
прокси одной строкой, затем создайте профиль. После этого
можно открыть браузер и войти вручную либо нажать «Импорт cookies» у нужного профиля.
Прокси можно вставить одной строкой в форме создания или настройки профиля:
`socks5://user:password@proxy.example.com:1080` либо
`user:password@proxy.example.com:1080` (без префикса используется SOCKS5).
Для HTTP укажите `http://` или выберите тип. Принимается и `host:port` без
авторизации. Строка видна в поле до сохранения; после сохранения пароль обратно
не показывается.
Для прокси с авторизацией приложение поднимает локальный посредник на 127.0.0.1:
он передаёт HTTP Basic или SOCKS5 username/password на указанный прокси.
Пароль хранится внутри Windows DPAPI и не возвращается в интерфейс.
Менять прокси и импортировать cookies нужно при закрытом окне профиля.
Поддерживаются JSON array (или объект с массивом cookies) и Netscape cookies.txt,
до 1 MB. Принимаются только домены instagram.com и его поддомены; истёкшие
cookies пропускаются. Приложение не читает cookies установленных браузеров.
Исходный файл пользователь выбирает самостоятельно, он не удаляется.

Профили хранятся в LocalAppData/ArtistLeadFinder/browser-sessions как файлы
Windows DPAPI текущего пользователя. Cookies не возвращаются React-интерфейсу,
не входят в CSV и настройки и не записываются в журнал.
«Открыть браузер» открывает отдельное окно Chromium с изолированным
контекстом для каждого профиля. Проверьте авторизацию на самой странице Instagram;
наличие sessionid не считается доказательством успешного входа.
Сессия сохраняется автоматически, когда окно профиля закрывают (и при выходе из
приложения). Кнопка «Сохранить сессию» сохраняет её сразу, не закрывая окно.
Сохраняются cookies; localStorage и другие данные страницы не переносятся.
Перед удалением сохранённой сессии закройте её окно. Удаление локальной копии
не отзывает сессию на сервере Instagram. DPAPI не защищает от программ,
работающих с полномочиями того же пользователя Windows.

Fingerprint не подменяется.

## Основной сценарий: скаут-источники → лиды
На экране «Поиск артистов» добавьте от 1 до 20 Instagram-аккаунтов музыкальных
СМИ/пабликов, по одному на строку, и нажмите «Найти лидов». Источники сохраняются.
Приложение открывает выбранную сессию, читает до 12 ссылок на публикации из
доступной сетки каждого источника и до 200 доступных комментариев под каждой
публикацией. Комментарии подгружаются ограниченным числом прокруток и раскрытий.
С одной публикации берётся не больше 30 новых кандидатов; общего лимита на запуск
нет. Дубли не расходуют эту квоту: автор, уже стоящий в очереди запуска или
проверенный в прошлых запусках, повторно не открывается, а его новый комментарий
добавляется к существующей оценке. Порядок сетки
может включать закреплённые старые публикации; полного покрытия нет.
При требовании входа очередь встаёт на паузу: войдите вручную и продолжите.
Темп задаётся в настройках («Темп сбора Instagram»): случайная пауза между
страницами (по умолчанию 8–20 с), лимит профилей в час (60) и за запуск (без
лимита). При лимите в час очередь ждёт и продолжает сама. Если Instagram
ограничил запросы, очередь встаёт на паузу и после продолжения выдерживает
перерыв (30 мин). Счётчики темпа сбрасываются при перезапуске приложения.
Недоступную страницу можно пропустить. Каждый новый запуск перечитывает комментарии.

Кандидаты — авторы комментариев, а не @упоминания из подписи или текста комментария.
Автор публикации должен совпасть с источником. Каждый кандидат открывается отдельно:
роль исполнителя проверяется по биографии, закрытые профили, СМИ, фан-страницы
и магазины исключаются. В доказательствах сохраняются текст комментария и источник.
Изображения, аудио/видео и скрытые API не анализируются. Это локальные объяснимые
правила, не LLM; нестандартные описания артистов могут быть пропущены.

Готовые лиды появляются автоматически, без ручного выбора кандидатов.
Три оценки соответствия услугам — биты, сведение/мастеринг, продвижение —
отделены от общей оценки профиля. Прямой запрос весит до 90, свежий релиз даёт
повод для продвижения (60), демо — для сведения (45), жанр рэп/R&B — слабый
сигнал для битов (25). Это не вероятность покупки или доказательство бюджета.
Сигнал из комментария приписывается его автору после проверки профиля;
отрицания подавляют сигнал. Неизвестная дата, будущая дата и возраст свыше
90 дней снижают оценку. Возраст оценок пересчитывается при первом чтении списка
за день, даже без нового браузерного запуска. Сохраняются цитата, источник,
URL публикации и дата (либо «неизвестна»), email из биографии и ссылка профиля.
Отклонённые и contacted-профили скрыты из списка для работы, CRM не сбрасывается.
До 100 результатов выводятся по приоритету. История не является фоновым
мониторингом: пользователь запускает следующий поиск кнопкой.
Подписи уже прочитанных публикаций берутся из кеша; их правки на сайте не отслеживаются.

Дополнительные инструменты (ручные ссылки, демонстрационные наборы)
перенесены в сворачиваемый блок ниже основного сценария.

## Сбор артистов из браузера
Откройте «Поиск артистов» → «Реальные артисты из браузера». Выберите сохранённую
сессию или вариант без cookies, затем нажмите «Открыть Instagram».
Найдите артиста вручную и откройте его профиль. Кнопка «Добавить открытого
артиста» читает доступную страницу, запускает анализ и показывает сохранённую
карточку с оценкой. Браузер не обращается к скрытым API и не читает сообщения.

Для очереди вставьте до 100 ссылок на профили или @имён, по одной на строку.
Очередь последовательно открывает страницы в выбранном окне и сохраняет
результаты в базу и историю. Не переключайте страницы этого окна во время
обработки. Есть пауза, продолжение и отмена. Запрос входа/подтверждения,
ограничение сайта, закрытое окно или таймаут чтения приостанавливают очередь.
После проверки браузера пользователь может явно продолжить работу.
При перезапуске незавершённое задание отмечается прерванным; список ссылок и
уже сохранённые результаты остаются в истории. Повторный запуск списка не
создаёт дублей артистов и сохраняет ручные статусы CRM.

Извлекаются доступные метаданные страницы: имя, bio, счётчики и внешняя ссылка.
Поддерживаются английские и русские обозначения счётчиков. Разметка Instagram
может измениться: чтение не гарантировано для любой страницы/локали.
Числа на сайте могут быть округлены. Последняя активность пока не извлекается.
Пропущенные поля отмечаются в карточке; неизвестные подписчики показываются
как «Нет данных», в CSV — пустая ячейка. Оценка неполного профиля предварительная.
Существующие значения не стираются отсутствующими полями нового наблюдения.
Источник instagram_browser можно выбрать в фильтрах базы.

Схема SQLite обновлена до версии 3 (таблицы скаутинга добавлены к browser_queues).
Старая версия приложения не открывает базу более новой схемы.
