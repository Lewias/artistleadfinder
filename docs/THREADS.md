# Локальный автопостинг Threads

Очередь, черновики, история и зашифрованные сессии хранятся на компьютере. Публикации выходят через сайт Threads в общем браузерном профиле Instagram. Отдельный сервер для планировщика не нужен.

При первом открытии новая сборка обновляет схему базы до 30. Сборки со схемой 28 или 29 после этого не откроют эту базу; для возврата потребуется совместимая сборка или предварительная резервная копия. Отдельная папка portable сама по себе не изолирует данные приложения.

## Подключение

1. Выберите канал **Threads → Аккаунты**. Здесь показаны те же браузерные профили, что и в Instagram: название, прокси, статус, кнопка браузера и меню действий. При необходимости создайте профиль кнопкой **Новый профиль**.
2. Нажмите **Браузер** в строке профиля. Threads откроется отдельной вкладкой в том же окне и с тем же прокси. Войдите в Threads и оставьте окно открытым до появления статуса «Подключён» в приложении. Проверка входа выполняется автоматически; есть и кнопка **Проверить вход**.
3. В меню строки можно сохранить сессию, изменить название и прокси или отключить Threads. Профили общие: изменения названия и прокси будут видны также в Instagram.

Сессии Instagram и Threads сохраняются раздельно внутри одного зашифрованного профиля, включая автоматическое сохранение при закрытии окна. Повторное подключение того же аккаунта сохраняет очередь и историю. При отключении браузерного аккаунта очередь останавливается; сессия общего профиля остаётся. Если в браузере открыт другой аккаунт, публикация останавливается до ручной проверки. Временное ограничение Threads также требует ручной проверки.

Когда приближается время поста, приложение открывает сохранённый браузерный профиль с его прокси. Во время публикации вкладка Instagram не перенаправляется: Threads использует отдельную вкладку. При истёкшей сессии нужно снова войти через кнопку открытия браузера. Вручную искать или вставлять токен не требуется: браузер использует собственную сессию сайта, которая не является токеном Graph API.

## Публикации и расписание

На странице **Публикации** находится всё управление постами и временем. В разделе **Расписание публикаций** задаётся ежедневное время для каждого подключённого аккаунта, например `10:00, 18:30`, и пауза публикаций с этого аккаунта. Новые посты могут использовать следующее свободное время из этого расписания. Уже назначенные даты автоматически не меняются.

Поддерживаются текстовые посты. В редакторе есть предпросмотр, проверка длины и ссылок, сохранение черновика, публикация сейчас, выбор конкретной даты или следующего времени по расписанию. Даты хранятся в UTC; интерфейс и ежедневное расписание используют часовой пояс компьютера.

Общая пауза Threads и пауза отдельного аккаунта останавливают расписание. Явная команда **Опубликовать сейчас** выполняет разовую публикацию даже при паузе расписания.

После длительного простоя старые публикации получают статус «Пропущен» вместо массовой отправки. Их можно перенести на следующие слоты. При неоднозначном результате отправки программа проверяет недавние публикации (в API-режиме — также контейнер). Если результат не удаётся установить, пост требует ручной проверки; повторное нажатие публикации автоматически не выполняется. Старый пост с тем же текстом без времени публикации не считается подтверждением новой отправки.

## Фоновая работа

В **Настройки → Фоновая работа** доступны сворачивание в трей при закрытии, запуск вместе с Windows, тихий автозапуск в трей, уведомления и запрет сна при наличии предстоящих постов. Запрет сна выключен по умолчанию.

В меню трея есть открытие окна, пауза автопостинга Threads, отдельная пауза рассылки и полный выход. Двойной щелчок по значку открывает окно. При полном выходе или выключенном/спящем компьютере публикации не выполняются.

## Проверка

`backend/tests/test_threads.py` проверяет очередь с подменой API и браузерного транспорта. `backend/tests/test_threads_browser.py` проверяет распознавание аккаунта, редактор и подтверждение публикации на локальных HTML-страницах, а также миграцию существующих API-аккаунтов. `scripts/smoke-threads-ui.py` проверяет интерфейс с настоящим локальным сервисом и тестовым браузером, сохраняя снимки в `build/threads-ui-review/`.

Эти проверки не публикуют реальные посты. Работа с текущей версией сайта Threads требует отдельной проверки на аккаунте владельца; изменения разметки сайта могут потребовать обновления браузерного транспорта.
