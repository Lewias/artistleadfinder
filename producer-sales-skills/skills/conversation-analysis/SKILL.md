# Анализ переписки → карточка лида

Сначала прочитай: `../../reference/guardrails.md`, `../../reference/qualification.md`, `../../reference/deal-stages.md`.

Источник методики: conversation-summarization, entity-extraction, intent-detection, sentiment-analysis, conversation-pause-intelligence (Sales-Skills, MIT), сведено в одну процедуру.

## Процедура

1. **Прочитай всю переписку целиком**, от старых сообщений к новым. Отметь, кто написал последним и когда.
2. **Факты (entity extraction).** Только то, что сказано прямо, с датой сообщения:
   - имя/ник, жанр и референсы, ссылки на треки;
   - дата или окно релиза;
   - деньги: упоминания цен, бюджета, прошлых трат, «when I get paid»;
   - кто решает (сам / менеджер / лейбл);
   - что продюсер обещал и выполнил ли (файл, пак, ссылка, ответ).
3. **Намерения в последних сообщениях артиста (intent).** Одно сообщение может нести несколько: интерес + возражение + вопрос. Типы: `buy_ready`, `price_question`, `interested`, `info_request`, `objection`, `timing_later`, `not_interested`, `opt_out`, `small_talk`, `unclear`. Opt-out проверяется **первым** и останавливает всё.
4. **Тон и динамика (sentiment).** Теплеет / ровно / остывает. Признаки остывания: ответы короче, дольше, без вопросов.
5. **Тишина (pause intelligence).** Если артист молчит — это «думает» (взял паузу после цены, сказал «let me check») или «остыл» (без объяснений, после серии коротких ответов)? Не считать тишину отказом.
6. **Оценка намерения купить** по таблице из `qualification.md`: сигналы с цитатами → баллы → метка → уверенность.
7. **Этап** по `deal-stages.md`. Только по фактам.
8. **Следующее действие** — одно, конкретное, с «когда». Если правильное действие — ничего не писать, так и сказать.

## Формат вывода

```
## [имя / ник] — [метка] [баллы]/100 (уверенность: [high|medium|low])
Канал: [IG / iMessage / email] · Последнее сообщение: [кто], [дата] · Этап: [stage]

**Факты**
- Релиз: … («цитата», дата) | неизвестно
- Деньги: … | неизвестно
- Решает: … | неизвестно
- Звучание / референсы: …

**Сигналы оценки**
- +20 спросил цену — «how much for this one?» (12.10)
- −15 два напоминания без ответа (14.10, 17.10)

**Тон:** [теплеет / ровно / остывает] — почему.
**Обещания продюсера:** [что обещал, выполнено ли] | нет
**Чего не хватает:** [какой вопрос квалификации задать следующим]

**Следующее действие:** [что] · [когда] · [канал]
**Черновик:** (если действие = написать; по правилам `follow-up` / `objection-handling` / `closing`)

**Предлагаемое обновление CRM** (не применено, нужно «да»): этап → …, заметка → …
```

## Правила
- Каждый вывод про артиста подкреплён цитатой или помечен как предположение («похоже, что…»).
- Неизвестное пишется «неизвестно», а не угадывается.
- Не путать вежливость с интересом: «sounds good» без вопроса — не покупка.
- Если продюсер должен ответить (артист написал последним с вопросом) — это первое, что видно в карточке.

## Пакетный режим (много переписок)
Сделай короткие карточки (заголовок + следующее действие) и отсортируй по приоритету из `deal-stages.md → Приоритет`. Подробные карточки — только для первых 5–10. Для поиска забытых лидов см. скилл `follow-up`.
