# Тесты

`scenarios.json` — 10 выдуманных диалогов и что должен заключить хороший анализ: метка и диапазон оценки, этап, следующее действие, нужен ли черновик, что в нём обязательно и что запрещено.

`examples/` — эталонные ответы скиллов на 6 сценариев (01, 03, 04, 05, 07, 10). Это примеры формата и качества, на них же проверяется сам чекер.

`check.py` — проверка без зависимостей (`python3` из коробки):
- структура: имена скиллов, описания, ссылки на reference-файлы;
- оценка ответов: метка, баллы, этап, следующее действие, наличие / отсутствие черновика;
- линт черновиков: фразы из «Не писать» в `voice.md`, цены не из `offers.md`, проценты, незаполненные `[…]`, длина под канал, пунктуация (кроме ссылок, `{{…}}` и `subject:` в email).

## Как прогнать свои ответы

1. В Claude Code с установленным плагином дай сценарий скиллу, например:
   «Разбери переписку из сценария 02-ghost-after-price в tests/scenarios.json скиллом follow-up. Ничего не отправляй.»
2. Сохрани ответ в `tests/outputs/02-ghost-after-price.md` (папка в `.gitignore`).
3. Запусти:

```bash
python3 tests/check.py tests/outputs
```

`FAIL` объясняет, что не так. `PASS` не значит «отлично»: черновики всё равно читай сам.

## Свои сценарии
Добавь объект в `scenarios.json` с уникальным `id`. Реальные переписки в репозиторий не клади: обезличь имена, ники и номера.

Соглашения в ответах, на которые опирается чекер:
- заголовок `## <кто> — <ready|hot|warm|cold|stop> <баллы>/100`;
- строка `Этап: <stage>`;
- строка `**Следующее действие:** …`;
- черновики — строки, начинающиеся с `>`. Соседние строки `>` = одно сообщение;
- значения, которые вставляет продюсер, — в `{{ДВОЙНЫХ_СКОБКАХ}}` (`{{PAY_LINK}}`, `{{PRODUCER_NAME}}`). `[в квадратных]` считается незаполненным и не пропускается.
